<Accordion title="Should I use the SDK or the REST API?">
Use an SDK for production integrations. The REST API may change without notice. See [API & SDK](/api-sdk) to choose between the TypeScript and Rust SDKs.
</Accordion>

<Accordion title="Which platforms do the SDKs support?">
- **TypeScript** supports modern browsers, Node.js, and [React Native](/setup/react-native).
- **Rust** supports Rust applications and can be wrapped for native Swift or Kotlin apps. Satora currently ships no Swift or Kotlin bindings. See the [Rust SDK README](https://github.com/satoraHQ/satora-sdk/blob/main/rust-sdk/README.md) for supported routes and examples.
</Accordion>

<Accordion title="Do I need an API key?">
No authentication is required to use Satora Swaps. You can optionally pass an API key for swap attribution and custom fee markup, but it is not required for creating or completing swaps. Sign up at [developer.satora.io](https://developer.satora.io) to get one — see [API Keys](/setup/api-keys) for how to configure it.
</Accordion>

<Accordion title="How do I handle errors and failed swaps?">
The SDK has built-in error handling. For common error codes and recovery strategies, see [Error Codes](/handle-failures/error-codes). For refunding stuck swaps, see:
- [Refund On-chain HTLC](/handle-failures/refund-onchain-htlc)
- [Refund EVM HTLC](/handle-failures/refund-evm-htlc)
- [Recover Swaps from Seed](/handle-failures/recover-swaps-from-seed)
</Accordion>

<Accordion title="What happens if a swap gets stuck?">
Swaps have built-in timeouts. If a swap isn't completed within the timelock period (typically 24 hours for the client side), funds are automatically refundable. The SDK can detect stuck swaps and initiate refunds. You can also recover swaps using your mnemonic seed phrase.
</Accordion>

<Accordion title="Can I integrate Satora Swaps into my backend and manage swaps for my users?">
Yes, but there are trust tradeoffs to consider. When your backend holds keys and manages swaps on behalf of users, your users are trusting you with custody. We can help you design a setup that minimizes or eliminates these tradeoffs - but it requires us to understand your architecture first. [Reach out to us](mailto:support@satora.io?subject=Backend%20Integration) and we'll work with you on a solution.
</Accordion>
